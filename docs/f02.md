# F02 · Atendimento pelo mock via Kafka

O cenário abre um caso de chat da Aurora, recebe uma orientação do mock,
continua a conversa e encerra o caso. O histórico é consultado com a
sessão da analista Bia.

## Acompanhe o fluxo

1. O webhook identifica o canal pela rota e valida a assinatura HMAC sobre
   os bytes do corpo. O Rails persiste a entrada e devolve `case_id` e
   `correlation_id`. A mesma entrada repete o recibo. Alterar os bytes com
   o mesmo `source_event_id` devolve HTTP 409.
2. Na mesma transação, o Rails salva a mensagem, a rodada e o outbox.
   O processo de envio lê o outbox e assina o POST para a ponte. A ponte
   devolve HTTP 202 após a confirmação do Kafka em `agent.requests`.
3. O mock lê o pedido e publica a proposta em `agent.events`, usando
   `case_id` como chave e um ID de resposta determinístico. A ponte entrega
   os bytes do evento ao Rails. Os dois consumidores confirmam seus offsets
   após concluir a respectiva entrega ou registrar a falha em `agent.failures`.
4. O Rails cruza marca, correlação, geração, rodada e pedido antes de aplicar
   a proposta. Um retorno repetido informa `duplicate`. Um retorno defasado
   informa `discarded` e grava auditoria. O Rails inclui a nova mensagem
   que chega durante uma rodada no próximo pedido. Uma proposta de resolução
   só encerra o caso quando todas as mensagens pendentes foram consideradas.
5. A API valida a sessão e a visibilidade por equipe, fila e marca. O
   histórico sai em ordem de `sequence`, com paginação por `after_sequence`.

A F02 usa a fila padrão da marca. As classificações incompletas e inválidas
ficam persistidas em `classification_pending` e `classification_review`.
A chamada ao Jev e a correção entram na F04. O retorno de handoff pode
registrar o resumo e mover o caso para `waiting_human`. A distribuição
humana entra na F03.

## Executar a demonstração

Use Docker com Compose e Python 3 no host. Na raiz da worktree, execute
o bloco abaixo em Bash. Os valores das credenciais são sintéticos.

```bash
export API_PORT=3102
export CLOUDWALK_CHANNEL_SECRET=f02-demo-channel-root
export CLOUDWALK_AGENT_REQUESTS_SECRET=f02-demo-requests
export CLOUDWALK_AGENT_EVENTS_SECRET=f02-demo-events
export CLOUDWALK_DEMO_PASSWORDS='{"bia@example.test":"f02-demo-bia"}'
export CLOUDWALK_AGENT_REQUEST_URL=http://cloudwalk-f02-requests:8080/webhooks/v1/agent/requests
export CLOUDWALK_AGENT_EVENTS_URL=http://api:3000/webhooks/v1/agent/events

docker compose -p cloudwalk_f02 up --build -d db_setup kafka_setup
docker compose -p cloudwalk_f02 wait db_setup kafka_setup
docker build -t cloudwalk-f02-integration integration

docker compose -p cloudwalk_f02 run --build --no-deps -d --service-ports --use-aliases --name cloudwalk-f02-api \
  -e CLOUDWALK_CHANNEL_SECRET -e CLOUDWALK_AGENT_EVENTS_SECRET -e CLOUDWALK_DEMO_PASSWORDS api

for role in requests events mock; do
  docker run -d --restart on-failure --name "cloudwalk-f02-$role" --network cloudwalk_f02_default \
    -v "$PWD/docs/contratos/schemas:/contracts:ro" \
    -e CLOUDWALK_CONTRACT_SCHEMA=/contracts/v1.json \
    -e CLOUDWALK_AGENT_REQUESTS_SECRET -e CLOUDWALK_AGENT_EVENTS_SECRET -e CLOUDWALK_AGENT_EVENTS_URL \
    cloudwalk-f02-integration "$role"
done

docker compose -p cloudwalk_f02 run --no-deps -d --name cloudwalk-f02-outbox \
  -e CLOUDWALK_AGENT_REQUEST_URL -e CLOUDWALK_AGENT_REQUESTS_SECRET \
  db_setup bundle exec rails runner script/f02_outbox.rb

channel_id=$(docker exec cloudwalk-f02-api bundle exec rails runner \
  'puts Operations::Brand.find_by!(code: "aurora").channels.find_by!(kind: "chat").id')

python3 script/check_f02.py --api "http://127.0.0.1:$API_PORT" --channel-id "$channel_id"
```

O verificador envia dois turnos, testa reentrega e conflito da entrada,
valida autenticação e consulta os dois tópicos Kafka. Também entrega de novo
os bytes dos retornos e confere que o histórico continua com quatro mensagens.

Os serviços da demonstração podem ser encerrados preservando os volumes.

```bash
docker rm -f cloudwalk-f02-outbox cloudwalk-f02-requests cloudwalk-f02-events cloudwalk-f02-mock cloudwalk-f02-api
docker compose -p cloudwalk_f02 down
```

## Testes

Com o serviço `db` do Compose em execução:

```bash
docker compose -p cloudwalk_f02 run --rm --no-deps -e RAILS_ENV=test db_setup \
  bundle exec rails db:prepare
docker compose -p cloudwalk_f02 run --rm --no-deps -e RAILS_ENV=test db_setup \
  bundle exec rails test
```

Para testar a ponte e o mock com clientes simulados, instale os requisitos de
`integration/requirements.txt` em um ambiente virtual Python e execute:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s integration -v
```

## Verificação da entrega

- Sete testes da ponte e do mock passaram com clientes simulados.
- As 43 fixtures JSON tiveram o resultado esperado. O PostgreSQL 18,
  em modo de processo único, confirmou as restrições de unicidade da
  entrada, retorno, caso aberto e rodada, além do vínculo entre fila e marca.
- A suíte Rails e a demonstração com Kafka real ficaram pendentes. O ambiente
  de execução bloqueou o acesso ao Docker e ofereceu Ruby 3.3.8. O backend
  exige Ruby 3.4.
