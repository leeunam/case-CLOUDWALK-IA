# F03 · Atendimento humano

Validação integrada em 2026-11-19 sobre a base `9be0efa`, com Ruby 3.4.12,
Rails 8.1.4.1, PostgreSQL 17, Solid Queue 1.7.2 e Kafka 4.4.0.

## Escopo entregue

- Handoff preserva o caso, resumo, referências e histórico; a distribuição
  escolhe um analista elegível com menor carga absoluta e desempate definido.
- Os ativos cabem numa única alternativa do perfil. A carteira conta ativos,
  espera e retomada, inclusive pendências de outra marca.
- Espera libera capacidade ativa e conserva a carteira. A resposta do cliente
  retoma o mesmo responsável quando marca, disponibilidade e perfil permitem.
- Preparar troca de marca bloqueia novas atribuições/retomadas. Ativos precisam
  ser concluídos ou transferidos; tentar colocá-los em espera nesse momento
  retorna `409` sem gravar mensagem nem efetivar a troca.
- Transferência e reconciliação de acesso revogado sinalizam também a marca
  em operação quando liberam uma vaga de carteira em outra marca.
- Escritas exigem sessão, CSRF, versão esperada e chave de idempotência;
  autorização e invariantes são revalidadas sob bloqueio.
- O mock escala o cenário `terminal`/`advanced`, independentemente da origem
  da classificação. O resumo cita a última mensagem que utiliza. O histórico
  completo permanece disponível ao humano. Reentrega gera os mesmos bytes.

As rotas novas incluem `PATCH /api/v1/session/operation`,
`POST /api/v1/cases/{id}/messages`, `POST /api/v1/cases/{id}/actions` e
`GET /api/v1/cases/{id}/audit`. O OpenAPI v1 permanece como contrato.
A interface de operação ainda será conectada na F05/F06.

## Reproduzir o fluxo HTTP e Kafka

O bloco abaixo usa Bash e credenciais sintéticas. Prepare o banco e os tópicos
com os dois primeiros comandos da seção anterior. Depois execute:

```bash
export API_PORT=3103
export CLOUDWALK_CHANNEL_SECRET=f03-demo-channel-root
export CLOUDWALK_AGENT_REQUESTS_SECRET=f03-demo-requests
export CLOUDWALK_AGENT_EVENTS_SECRET=f03-demo-events
export CLOUDWALK_DEMO_PASSWORDS='{"bia@example.test":"f03-demo-bia","supervisor@example.test":"f03-demo-supervisor"}'
export CLOUDWALK_AGENT_REQUEST_URL=http://cloudwalk-f03-requests:8080/webhooks/v1/agent/requests
export CLOUDWALK_AGENT_EVENTS_URL=http://api:3000/webhooks/v1/agent/events

rtk docker build -t cloudwalk-f03-integration integration
rtk docker compose -p cloudwalk_f03 run --build --no-deps -d --service-ports --use-aliases --name cloudwalk-f03-api \
  -e CLOUDWALK_CHANNEL_SECRET -e CLOUDWALK_AGENT_EVENTS_SECRET -e CLOUDWALK_DEMO_PASSWORDS api

for role in requests events mock; do
  rtk docker run -d --restart on-failure --name "cloudwalk-f03-$role" --network cloudwalk_f03_default \
    -v "$PWD/docs/contratos/schemas:/contracts:ro" \
    -e CLOUDWALK_CONTRACT_SCHEMA=/contracts/v1.json \
    -e CLOUDWALK_AGENT_REQUESTS_SECRET -e CLOUDWALK_AGENT_EVENTS_SECRET -e CLOUDWALK_AGENT_EVENTS_URL \
    cloudwalk-f03-integration "$role"
done

rtk docker compose -p cloudwalk_f03 run --no-deps -d --name cloudwalk-f03-worker db_setup bundle exec ruby bin/jobs
rtk docker compose -p cloudwalk_f03 run --no-deps -d --name cloudwalk-f03-outbox \
  -e CLOUDWALK_AGENT_REQUEST_URL -e CLOUDWALK_AGENT_REQUESTS_SECRET db_setup bundle exec rails runner script/f02_outbox.rb
```

Em um banco exclusivo para a demonstração, configure a Bia como única analista
disponível e acrescente uma alternativa de capacidade para o cenário do mock.
Esse ajuste de dados de ensaio não altera os padrões do seed. A configuração
pela interface pertence à F06.

```bash
rtk docker exec cloudwalk-f03-api bundle exec rails runner '
  bia = Operations::User.find_by!(email: "bia@example.test")
  Operations::User.where(role: "analyst").where.not(id: bia.id).update_all(available: false)
  bia.update!(available: true)
  profile = bia.capacity_profiles.find_by!(active: true)
  pair = [{"priority" => "advanced", "category" => "terminal", "limit" => 1}]
  profile.update!(alternatives: profile.alternatives + [pair]) unless profile.alternatives.include?(pair)
'

channel_id=$(rtk docker exec cloudwalk-f03-api bundle exec rails runner \
  'puts Operations::Brand.find_by!(code: "aurora").channels.find_by!(kind: "chat").id')
rtk proxy python3 -B script/check_f03.py --api "http://127.0.0.1:$API_PORT" --project cloudwalk_f03 --channel-id "$channel_id"
```

Para encerrar, preservando os volumes da demonstração:

```sh
rtk docker rm -f cloudwalk-f03-outbox cloudwalk-f03-worker cloudwalk-f03-requests cloudwalk-f03-events cloudwalk-f03-mock cloudwalk-f03-api
rtk docker compose -p cloudwalk_f03 down
```

Aguarde a estabilização do grupo Kafka após recriar consumidores. Recuperação,
encerramento gracioso e ensaios de carga continuam em F07/F08. O ambiente
isolado usado pelo integrador foi encerrado após as verificações.
