# Demonstração local com SetFit R1

A instalação reproduzida usou o código `89b9e68f6473c16da898d7021b5d18be211942cb`, o pacote portátil da adoção D018 e dois volumes novos de PostgreSQL e Kafka. O Rails preserva a classificação fornecida pelo canal. Quando falta prioridade ou categoria, pede ao SetFit R1 o complemento. O atendente que responde no chat continua sendo o simulado via Kafka.

## Obter código e modelo

1. Receba do responsável o repositório Git que contém a revisão indicada. Para reproduzir a partir de uma entrega Git local, execute os comandos abaixo em um diretório com espaço disponível. Também é possível clonar um remoto que já contenha essa revisão.
2. Solicite ao custodiante da entrega o arquivo **setfit-r1-package.tar.gz**, o recibo e a atribuição. O pacote é externo ao Git. A entrega local fornece o arquivo por transferência direta, sem hospedagem permanente dos pesos. Guarde o original e escolha um diretório **novo** para extração. O diretório pai precisa existir.
3. Use Git, Python 3.11 e Docker com Compose 2.24.4 ou posterior e suporte a Linux amd64. A primeira construção em host sem cache requer acesso aos registros de imagens, PyPI e PyTorch CPU. O pacote contém os pesos para inferência local. A demo cria as chaves e senhas sintéticas no clone.

```sh
git clone --no-local --single-branch --branch main /caminho/do/repositorio helpdesk-c07
cd helpdesk-c07
git checkout --detach 89b9e68f6473c16da898d7021b5d18be211942cb
git status --short
git rev-parse HEAD

ARQUIVO=/caminho/recebido/setfit-r1-package.tar.gz
MODELO=/caminho/escolhido/setfit-r1
sha256sum "$ARQUIVO"
python3 -B -m script.classification_comparison.setfit_sf2.serving.provision "$ARQUIVO" "$MODELO"
sha256sum "$MODELO/manifest.json"
```

| --- | --- |
| Arquivo portátil | 870.201.575 bytes · SHA-256 `a06d4eb0fdf26f06a86b6fe6fa1f8e1bdab49fbed01647a0b8431193473e4f01` |
| Instalação | 37 arquivos regulares · 975.492.998 bytes · SHA-256 do manifesto `224c572b0a2c6ce93b1dd1b90317df131cbb47b897b4de38e97659fbc7e57872` |
| Política de decisão R1 | Categoria 0,95 e prioridade 0,70, margens 0. SHA-256 `127eb227ac174384700a60390272a48abdca9a81592086dde5bc132727338473` |

O instalador valida o arquivo e o manifesto. O serviço valida os membros, as políticas e o código qualificado antes da prontidão. A montagem de `/model` é somente leitura. O catálogo ativo de cada marca precisa usar os códigos e as descrições exatos do catálogo adotado. Subconjuntos são compatíveis. A classificação inclui Pix, Repasses e Maquininha, com prioridades Básica, Intermediária, Avançada e Urgente. Um catálogo incompatível para complemento leva à revisão. ## Iniciar e verificar

Escolha um nome de projeto inédito começando com `cloudwalk_demo_` e duas portas livres em loopback. Esta função de shell conserva os argumentos em cada operação.

```sh
PROJETO=cloudwalk_demo_minhaprova
API=43347
WEB=45347
demo_real() {
  python3 -B script/demo.py --project "$PROJETO" --api-port "$API" --web-port "$WEB" \
    --classifier setfit --model-dir "$MODELO" "$@"
}
demo_real config
demo_real up
demo_real status
docker exec "$PROJETO-setfit-1" python -c "from urllib.request import urlopen; print(urlopen('http://localhost:8080/ready').read().decode())"
docker inspect --format '{{range .Mounts}}{{println .Destination .RW}}{{end}}' "$PROJETO-setfit-1"
```

A saída de `up` informa as URLs. Com as portas acima, abra o [simulador](http://127.0.0.1:45347/) e a [operação](http://127.0.0.1:45347/analista) em perfis separados. Use a página inicial do simulador ligada à API. O link **Abrir demonstração local** na página abre uma simulação inteiramente no navegador. Para obter uma senha, execute, por exemplo, `demo_real login supervisor@example.test`. Conserve o `.env.demo.local` criado no clone, o diretório do modelo e o nome do projeto para reiniciar.

A prontidão informa `ready: true`, o PID e contadores. A montagem deve mostrar `/model false`. Se o pacote estiver ausente, `config` informa “Informe --model-dir com o pacote SetFit R1 instalado” e interrompe a partida. No controle isolado sem pesos, a imagem respondeu HTTP 503 a `/ready`, com `ready: false`, PID nulo e duas falhas de partida. Se um diretório tiver manifesto e membros divergentes, consulte `demo_real status` e `demo_real logs setfit`; o worker aguarda a saúde do classificador. Reponha o pacote aprovado em um destino novo, confirme os hashes e repita a subida com o novo caminho. Em `503 busy` confira o contador de recusas e as tentativas registradas pelo Rails. Em `422 text_out_of_scope`, o relato excedeu 128 tokens para o especialista solicitado. [Guia do serviço](../script/classification_comparison/setfit_sf2/serving/README.md).

## Percorrer os três canais

No simulador, escolha **Novo atendimento**, depois **Marca** e **Canal**. Abra **Classificação da mensagem**. Os seletores começam preenchidos de acordo com o canal. Clique em **Categoria** para escolher a opção indicada e, separadamente, em **Prioridade**. Para omitir ambos, escolha **Não informar** nos dois seletores. Digite a mensagem e clique em **Enviar mensagem**.

| Marca e canal | Categoria / prioridade | Mensagem sintética e resultado observado |
| --- | --- | --- |
| Aurora Pagamentos · WhatsApp | Maquininha / Avançada | “A tela da maquininha do quiosque ficou preta durante o último pagamento.” A entrada segue direto, e o atendente propõe handoff. Na operação, abra o caso como analista atribuído, leia o resumo, responda e clique em **Resolver atendimento**. |
| Horizonte Negócios · E-mail | Pix / **Não informar** | “Urgente. O Pix parou em todos os caixas da padaria. Nenhum pagamento entra e as vendas estão totalmente interrompidas.” O SetFit completa somente a prioridade com Urgente. Atualize a conversa para ver a resposta do atendente simulado. |
| Aurora Pagamentos · Chat | **Não informar** / **Não informar** | “Boa tarde. Abri este atendimento para conversar, mas ainda não tenho detalhes.” O caso aguarda revisão. Na supervisão abra **Em revisão**, selecione o caso e expanda **Corrigir classificação**. Informe Repasses, Básica e o motivo, depois aplique. O atendente responde após a correção. |

Entre como Bia para conferir a lista e o histórico da Aurora. A mesma conta recebe HTTP 404 ao tentar abrir o caso Horizonte diretamente. Alex acessa os dois. Guarde o ID e a quantidade de mensagens de cada caso. Execute `demo_real down`, depois `demo_real up` e reabra os históricos. A C07 conferiu os IDs de mensagens, o estado, a auditoria, as tentativas e os IDs Kafka antes e depois de recriar a pilha. Ao terminar, execute `demo_real down`.

**Exercício.** Siga o e-mail Horizonte no recibo do simulador e na auditoria. Identifique a categoria de origem `channel`, a prioridade de origem `setfit` e a tentativa com uma chamada ao especialista de prioridade. Procure o mesmo `correlation_id` no pedido e na resposta Kafka. O campo `request_event_id` da resposta aponta para o ID do pedido. [Registro do exercício](evidencias/c07/setfit.json).

## Resultados e repetição

A instalação foi medida em Linux x86-64, Intel Core i5-1345U com 12 processadores lógicos, 15 GiB de RAM, Python 3.11.13, Docker Engine 29.3.0 e Compose 5.1.0. Havia cerca de 8,6 GiB de RAM disponíveis na preparação. O clone local ocupou 48 MiB em disco. Os dez serviços somaram 3.898.183.680 bytes de memória corrente ao fim dos casos. O pico do contêiner SetFit foi 2.623.467.520 bytes. A imagem SetFit ocupou 1,72 GB reportados pelo Docker. O host já tinha camadas de build em cache. Com o arquivo e a árvore instalada juntos são 1.845.694.573 bytes, além do clone, imagens, volumes e espaço de construção. Estes valores descrevem esta execução sequencial.
