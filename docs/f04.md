# F04 · Adaptador Jev isolado

Primeira fatia validada no runtime do projeto em 2026-11-19. Esta entrega não
conclui a F04: jobs, persistência de tentativas/evidências, revisão/correção
operacional e transições do atendimento ainda serão conectados ao adaptador.
O recebimento atual continua preservando casos sem classificação em pendência.

## Interface

`Classification::Jev::Classifier.new(client:, categories:, priorities:)`
recebe catálogos ativos em mapas de código para descrição. Sua operação
`call(text:, category:, priority:)` aceita campos ausentes e devolve um resultado
com `status`, `classification`, `issues`, `evidence`, `retryable` e
`retry_after_seconds`.

- `HttpClient` usa a API System One e `FixtureClient` permite execução sem chave.
- Somente campos ausentes geram perguntas Choice; campos válidos são preservados.
- Entrada inválida não chama o fornecedor. Abstenção, resposta inválida ou falha
  de transporte produz `review`, preservando dados válidos do canal.
- A evidência guarda modo, modelo solicitado/retornado, latência e os valores de
  escolha, probabilidades e confiança disponíveis. Não há limiar de confiança.
- Cada chamada faz uma tentativa. Repetição e respeito ao atraso informado serão
  responsabilidades do futuro job, usando `retryable` e `retry_after_seconds`.
- Catálogos de prioridades aceitam subconjuntos de `basic`, `intermediate`,
  `advanced`, `urgent`. A opção `informacao_insuficiente` é reservada; cada
  pergunta comporta até 254 opções operacionais e a opção de abstenção.
  O futuro consumidor/configurador deve validar essas restrições ao montar o
  catálogo. Configuração inválida é rejeitada pelo construtor.

Referências conferidas: [Choice](https://docs.typesafe.ai/primitives/choice) e
[System One](https://docs.typesafe.ai/api/system-one). O endpoint é
`https://api.typesafe.ai/v1/systemone` e o modelo padrão solicitado é `jev-latest`.
O modelo retornado é registrado separadamente.

## Verificação executada

- No Ruby 3.4.12 do Docker, os testes isolados executaram **26 testes e 262
  asserções**, sem falhas nem erros. O ensaio real foi pulado.
- A suíte conjunta Rails executou 48 testes e 657 asserções, com zero falhas,
  zero erros e um teste pulado: o mesmo ensaio real Jev.
- As regressões cobrem caminhos de fixtures no host/Compose, corpo/modelo com
  UTF-8 inválido, gzip corrompido, prioridades fora do contrato, preservação,
  abstenção, resposta incompleta, timeout, rede, HTTP e evidências.
- O carregamento antecipado do Rails passou. As 43 fixtures contratuais tiveram
  o resultado esperado.

O ensaio real ficou pendente: `TYPESAFE_API_KEY` não estava configurada. Os
testes locais não demonstram acerto, latência ou disponibilidade do modelo real.
A cobertura de `Retry-After` com data HTTP futura e relógio fixo é uma melhoria
de teste pendente; a data vencida e o atraso em segundos estão cobertos.

## Reproduzir

Na raiz do checkout, com o banco preparado conforme o roteiro F03:

```sh
rtk docker compose -p cloudwalk_f03 run --rm --no-deps -e RAILS_ENV=test db_setup \
  bundle exec rails test test/services/classification/jev
```

Para o ensaio real, carregue `TYPESAFE_API_KEY` no ambiente do terminal e execute
explicitamente:

```sh
rtk docker compose -p cloudwalk_f03 run --rm --no-deps \
  -e TYPESAFE_API_KEY -e JEV_LIVE_TEST=1 db_setup \
  bundle exec ruby test/services/classification/jev/live_test.rb
```

O teste usa texto sintético, exige a categoria Pix preenchida pelo Jev, preserva
a prioridade recebida e mostra evidências do fornecedor. Esse comando não foi
executado contra o serviço real nesta rodada por falta da credencial.
